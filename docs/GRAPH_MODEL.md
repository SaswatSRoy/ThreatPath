# ThreatPath FalkorDB Graph Data Model

## 1. Schema Overview

ThreatPath models security events as a connected causal graph rather than isolated flat logs. The graph differentiates between:
1. **Direct Observations**: Telemetry recorded by endpoint agents or network sensors (e.g. host executing process).
2. **Knowledge-Base Mappings**: Static industry taxonomy alignments (e.g. event mapping to MITRE ATT&CK technique, software affected by CVE).
3. **Inferred Connections & Access Paths**: Network topology permissions (e.g. host can access critical database).
4. **Provenance & Governance**: Audit trails generated by the agent during investigation.

---

## 2. Node Schema & Properties

| Node Label | Key Properties | Description |
| :--- | :--- | :--- |
| `Alert` | `id`, `title`, `description`, `severity`, `status`, `timestamp`, `source`, `alert_type` | Security detection triggered by sensor or SIEM. |
| `Event` | `id`, `event_type`, `timestamp`, `description`, `action_status` | Discrete system occurrence (logon, file write, network connect). |
| `Identity` | `id`, `username`, `email`, `role`, `department`, `privilege_level` | Human or service account associated with the event. |
| `Host` | `id`, `hostname`, `ip_address`, `os`, `environment`, `isolated` | Computing endpoint or virtual machine. |
| `Process` | `id`, `name`, `pid`, `command_line`, `hash`, `executed_by` | OS process launched on a host. |
| `Indicator` | `id`, `value`, `indicator_type`, `reputation`, `malicious_score` | Network or file indicator of compromise (IP, domain, hash). |
| `Technique` | `id`, `mitre_id`, `name`, `tactic`, `description` | MITRE ATT&CK adversarial tactic or technique. |
| `Software` | `id`, `name`, `version`, `vendor` | Installed software package or runtime framework. |
| `Vulnerability` | `id`, `cve_id`, `cvss_score`, `cisa_kev`, `description` | Disclosed vulnerability catalogued in CVE and CISA KEV. |
| `Asset` | `id`, `name`, `asset_type`, `criticality`, `data_classification` | High-value business asset (customer DB, payment gateway). |
| `Investigation` | `id`, `started_at`, `completed_at`, `classification`, `priority`, `raw_score`, `narrative` | Agent investigation record and analytical provenance. |
| `ResponseAction`| `id`, `action_type`, `target_entity`, `status`, `policy_decision`, `justification`, `proposed_at` | Simulated defensive response action governed by policy gate. |

## 3. Relationship Semantics

| Source Node | Edge Type | Target Node | Category | Semantic Meaning |
| :--- | :--- | :--- | :--- | :--- |
| `(Alert)` | `[:HAS_EVENT]` | `(Event)` | Direct Observation | Links an alert envelope to its constituent telemetry events. |
| `(Event)` | `[:INVOLVES_IDENTITY]` | `(Identity)` | Direct Observation | Identifies the authenticated principal initiating the event. |
| `(Event)` | `[:OCCURRED_ON]` | `(Host)` | Direct Observation | Pinpoints the physical or virtual host where event took place. |
| `(Event)` | `[:INVOLVES_PROCESS]` | `(Process)` | Direct Observation | Associates authentication or system activity with process context. |
| `(Host)` | `[:EXECUTED]` | `(Process)` | Direct Observation | Proves that the host kernel spawned and executed the binary. |
| `(Process)` | `[:CONNECTED_TO]` | `(Indicator)` | Direct Observation | Records outbound socket connection from process to remote IP/host. |
| `(Event)` | `[:MAPS_TO]` | `(Technique)` | Knowledge Mapping | Enriches raw telemetry with MITRE ATT&CK categorization. |
| `(Host)` | `[:RUNS]` | `(Software)` | Inventory Mapping | Catalogues software packages and versions active on the endpoint. |
| `(Software)` | `[:AFFECTED_BY]` | `(Vulnerability)`| Vulnerability Intel | Correlates installed version against CVEs and CISA KEV. |
| `(Host)` | `[:CAN_ACCESS]` | `(Asset)` | Access Topology | Models network reachability and ACL permissions to critical assets. |
| `(Investigation)`| `[:INVESTIGATES]` | `(Alert)` | Provenance | Links the agent's investigation audit trail to the target alert. |
| `(Investigation)`| `[:RECOMMENDED_ACTION]`| `(ResponseAction)`| Governance | Binds the recommended defensive response to the investigation. |

## 4. Schema Indexes in FalkorDB

Schema indexes ensure $O(1)$ and $O(\log N)$ vertex resolution during real-time multi-hop investigations:

```cypher
CREATE INDEX FOR (a:Alert) ON (a.id);
CREATE INDEX FOR (e:Event) ON (e.id);
CREATE INDEX FOR (i:Identity) ON (i.id);
CREATE INDEX FOR (h:Host) ON (h.id);
CREATE INDEX FOR (p:Process) ON (p.id);
CREATE INDEX FOR (ind:Indicator) ON (ind.id);
CREATE INDEX FOR (v:Vulnerability) ON (v.id);
CREATE INDEX FOR (ast:Asset) ON (ast.id);
CREATE INDEX FOR (inv:Investigation) ON (inv.id);
CREATE INDEX FOR (ra:ResponseAction) ON (ra.id);
```

## 5. Scenario Topologies in the Seed Dataset

### Scenario A: Correlated Activity (`alert-sec-001`)
```
(Alert: alert-sec-001)
   |
   +--> [:HAS_EVENT] --> (Event: evt-101)
                            |
                            +--> [:INVOLVES_IDENTITY] --> (Identity: jdoe [ELEVATED])
                            +--> [:OCCURRED_ON] --------> (Host: jump-prod-01)
                            |                                |
                            |                                +--> [:EXECUTED] --> (Process: powershell.exe)
                            |                                |                       |
                            |                                |                       +--> [:CONNECTED_TO] --> (Indicator: 198.51.100.44 [MALICIOUS])
                            |                                +--> [:CAN_ACCESS] -> (Asset: Customer DB [CRITICAL])
                            +--> [:MAPS_TO] ------------> (Technique: T1059.001, T1078)
```
*Outcome*: Full multi-hop causal chain verified; classified as `likely_compromise`, remediation priority `critical`.

### Scenario B: Insufficient Evidence (`alert-sec-002`)
```
(Alert: alert-sec-002) --> [:HAS_EVENT] --> (Event: evt-201)
                                               |
                                               +--> [:INVOLVES_IDENTITY] --> (Identity: mchen)
                                               +--> [:OCCURRED_ON] --------> (Host: auth-gateway)
```
*Outcome*: No downstream processes, no C2 connection, no critical database access. Classified as `insufficient_evidence`, remediation priority `low`.

### Scenario C: Vulnerable But Not Compromised (`alert-sec-003`)
```
(Alert: alert-sec-003) --> [:HAS_EVENT] --> (Event: evt-301)
                                               |
                                               +--> [:OCCURRED_ON] --------> (Host: api-gw-dmz-02)
                                                                                |
                                                                                +--> [:RUNS] ---------> (Software: Struts 2.5.20)
                                                                                |                          |
                                                                                |                          +--> [:AFFECTED_BY] -> (Vuln: CVE-2023-50164 [KEV])
                                                                                +--> [:CAN_ACCESS] ----> (Asset: Payment Gateway [HIGH])
                                                                                +--> [:EXECUTED] -----> (Process: java [Normal])
```
*Outcome*: High remediation priority due to KEV vulnerability on accessible host, but classified as `suspicious` (exposure) rather than `likely_compromise` because no hostile child processes or beaconing exist. Recommended response is `SIMULATE_ESCALATE_INCIDENT` (patch management ticket), strictly distinguishing exposure from active compromise.

### Scenario D: Disconnected Entities & Blocked Attempts (`alert-sec-004`)
```
(Alert: alert-sec-004) --> [:HAS_EVENT] --> (Event: evt-401 [BLOCKED])
                                               |
                                               +--> [:OCCURRED_ON] --------> (Host: bastion-stage.corp.internal)

(Indicator: ind-unrelated-scanner {value: "203.0.113.88"})  <-- [DISCONNECTED / ZERO GRAPH EDGES]
```
*Outcome*: All SSH password spray attempts were blocked by host security controls (`action_status: BLOCKED`). FalkorDB graph traversal confirms zero active sessions, zero child processes, zero lateral movement, and zero critical asset reachability. The external malicious scanner indicator in the database is completely disconnected. Classified as `insufficient_evidence`, remediation priority `low`, proving that ThreatPath does not fabricate correlations between unlinked entities.

## 6. Custom Scenario Data Model & Session Scoping

ThreatPath supports user-submitted custom scenarios via the **Custom Scenario Lab**.

### Node Schema: `CustomScenario`
| Property | Type | Description |
| :--- | :--- | :--- |
| `id` | `STRING` | Unique scenario identifier (`scenario-<alert_id>`). |
| `name` | `STRING` | Human-readable scenario title. |
| `description` | `STRING` | Detailed scenario description or hypothesis. |
| `schema_version` | `STRING` | Supported scenario specification version (`1.0`). |
| `session_id` | `STRING` | Session identifier (`X-Session-ID`) establishing data boundary. |
| `created_at` | `STRING` | ISO 8601 creation timestamp. |
| `alert_id` | `STRING` | Identifier of the scenario's constituent `Alert` node. |

### Topology:
```
(CustomScenario: scenario-alert-custom-001) --> [:CONTAINS_ALERT] --> (Alert: alert-custom-001)
                                                                           |
                                                                           +--> [:HAS_EVENT] --> (Event: ...)
```

### Session Isolation Model:
All custom scenario nodes (`CustomScenario`, `Alert`, and constituent entities/relationships) carry a `session_id` property. When a client provides `X-Session-ID: <session_uuid>`, queries filter:
```cypher
MATCH (a:Alert) WHERE (a.session_id IS NULL OR a.session_id = $session_id)
```
- **Seeded alerts** (`session_id IS NULL`): Globally accessible to all users for demonstration.
- **Custom alerts** (`session_id = $session_id`): Accessible only to the session that authored them.
